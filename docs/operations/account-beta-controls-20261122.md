# Профиль, регистрация и доступ к закрытой бете

## Поведение

Аватар в левой карточке профиля — кнопка «Изменить аватар». Она открывает модальный редактор: выбор файла, обрезка, сохранение, удаление. Выбор рамки расположен отдельно; «Без рамки» доступно всегда. Два представления синхронизируются после ответа сервера, при потере ответа доступно обновление без автоматического повтора.

Night сохраняет исходные цвета дракона каталога; затемнение остаётся. Центральные иллюстрации глав не меняются.

На странице произведения «Моё чтение» содержит прогресс и настройки обновлений. Дублирующая форма приватных оценок и заметки убрана. Ничего из старых данных не удаляется и не публикуется; экспорт дневника сохраняет прежние данные. Публичная оценка редактируется через отзывы.

## Три независимых разрешения

- `site_access_policy.public_registration`: разрешает публичную email-first регистрацию без приглашения. Начальное значение **false**.
- `site_access_policy.beta_only`: допускает к содержимому только отмеченных участников беты и ADMIN. Начальное значение **false**, чтобы не заблокировать существующих читателей до проверки списка участников.
- `user_appearance.beta_frame_granted`: отдельная награда; участие в бете само по себе её не выдаёт.

Управление: профиль ADMIN → «Регистрация и доступ» → админка «Приглашения». Права ADMIN перепроверяются сервером и в транзакции. Сохранения имеют revision fence и аудит. Потерянный ответ не повторяется автоматически: сначала обновить настройки.

При включённом ограничении беты анонимные посетители и неучастники, включая EDITOR, попадают на `/beta-wait`. API содержимого и изменения данных возвращают 403. Вход, выход, приглашённая регистрация, подтверждение почты, восстановление пароля и readiness остаются доступны. Роль ADMIN — исключение для сохранения управления. Пароли и сессии не отзываются. После изменения членства доступ пересчитывается со следующего запроса; уже показанный в браузере контент нельзя отозвать задним числом.

Открытая регистрация не означает участие в бете. При public_registration=true и beta_only=true обычный зарегистрированный пользователь после подтверждения почты ожидает релиза.

## Приглашения

ADMIN выбирает «Участник закрытой беты после подтверждения почты». Новый интерфейс предлагает эту галочку включённой. Ссылка без неё даёт обычную регистрацию при закрытом публичном приёме. Для совместимости прежний API `{email}` создаёт обычное приглашение; неизвестные поля и не-boolean grantsBeta отклоняются.

`grants_beta` сохраняется при создании приглашения. Открытие ссылки и pending-аккаунт членства не дают. Только успешная активация атомарно устанавливает beta_participant, увеличивает revision оформления и записывает событие с автором приглашения. Аватар, выбранная рамка и отдельная награда сохраняются. Ошибка записи участия откатывает также подтверждение почты, consumption токена и активацию приглашения. Сроки, отзыв, конкуренция и одноразовость используют прежний механизм. Старые приглашения получают false; уже существующие аккаунты автоматически не переопределяются. Их участников ADMIN отмечает в «Участниках беты».

## Контракт AUTH

Ни одного изменения production Compose, env, 18 runtime-флагов, recovery, DB gates, поколений или закрытого legacy-пилота не требуется.

В текущем invitation runtime (оба AUTH_BETA_INVITATION_*_ENABLED=true) право публичного приёма теперь делегируется ADMIN-настройке БД. `REGISTRATION_ENABLED=false` сохраняется: этот прежний флаг больше не управляет новым режимом публичной регистрации. Экстренное отключение AUTH_BETA_INVITATION_REGISTRATION_ENABLED блокирует публичный и приглашённый приём; AUTH_BETA_INVITATION_DISPATCH_ENABLED и остальные существующие activation readiness/worker/gate проверки продолжают ограничивать отправку. Не включать публичную регистрацию при выкладке.

Публичные pending_activation задания проходят существующие claim → fence → reservation → committed start → одноразовый sender. При claim и перед start проверяются актуальная политика под SHARE lock, activation gate и совместимость закрытого пилота. Invitation задания сохраняют обязательную привязку к живому приглашению. Legacy задания не получают нового разрешения, pin и расходованный бюджет не меняются. Закрытие публичного приёма блокирует ещё не начатую отправку публичных заданий; уже начатый HTTP отменить нельзя. Полученный код остаётся пригоден для завершения активации. Неоднозначные задания не переотправляются автоматически.

## Миграция и выкладка

0053_site_access_policy — аддитивная: singleton с обоими false, журнал аудита, grants_beta=false у прежних приглашений. Ожидаемый journal: 53 → 54. Штатная цепочка backup → migrator → app → HTTPS smoke. Существующие данные сохраняются. Предыдущий image проверяется на новой схеме при начальной политике false/false. Старый image не реализует новые ограничения доступа: совместимость схемы не означает поддержку beta_only при будущем откате.

Не менять режимы production для проверки. Все реальные тесты регистрации/отправки — только с отдельным разрешением; автоматические сценарии используют disposable PG17 и mock HTTP. При сбое production deploy/HTTPS — остановиться с диагностикой, без повторного deploy или ручного rollback.
