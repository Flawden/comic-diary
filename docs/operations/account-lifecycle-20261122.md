# Управление аккаунтами

В `/admin/users` ADMIN может заблокировать, разблокировать или удалить пользователя.
Блокировка сохраняет профиль и публикации, немедленно отзывает сессии и открытые коды
восстановления/активации. Разблокировка требует нового входа, прежние сессии не оживают.
Удаление другого пользователя требует подтверждения его ID и отдельного подтверждения
в браузере. USER и EDITOR не получают этих прав. ADMIN удаляет себя только через профиль.

`/account/delete` требует действующей сессии, текущего пароля и слова `УДАЛИТЬ`.
Страница, API удаления и защищённый экспорт дневника доступны владельцу аккаунта
даже без участия в закрытой бете; остальной контент остаётся под прежним ограничением.
Чужой ID не принимается в self-service API. Все POST проверяют Origin, ограничивают
тело, используют rate limit; роль, активность и конкретная сессия повторно проверяются
в транзакции. Последний активный ADMIN защищён общим authority advisory lock, включая
одновременное удаление двух администраторов и прежний путь смены роли/активности.

Удаление необратимо: очищаются имя, адрес и пароль профиля, все сессии, личный дневник,
прочтения, личные произведения с архивными редакциями, оформление, привилегии и реакции.
Стабильный ID с неактивной обезличенной записью остаётся для ссылочной целостности.
Отзывы, оценки и ответы остаются опубликованными с подписью «Удалённый пользователь».
Роль технической записи USER, пароль NULL, восстановить её активацией или админским
переключением нельзя. Это не просто скрытие активного профиля.

Ограничения хранения: прежние приглашения (включая привязанный email), использованные
и отозванные challenge-записи, зашифрованные outbox, аудит и резервные копии не стираются.
Закрытый legacy pilot и его pin/расходованный бюджет неизменны. Нормализованный файл
аватара остаётся в append-only media для совместимости с backup; потеря DB-ссылки делает
его публичный URL недоступным. Удаление аккаунта не заявляет полную очистку архивов.

Миграция 0054 только добавляет deleted_at, constraint, журнал lifecycle и защитные
триггеры от поздней записи личного состояния уже удалённому пользователю. Существующие
пользователи и AUTH-конфигурация не меняются. Порядок блокировок: activation control →
recovery control → authority → users по ID → session → tokens. Строки control только
блокируются на время операции, gate/generation/pilot не обновляются. Сбой очищения или
записи аудита откатывает всю транзакцию. Уже начатую отправку письма отменить невозможно;
не начатая отправка использует прежние проверки активности и отозванного кода.

Проверки: disposable PG17 migration preservation/replay/old SQL, восстановление
целостного snapshot при ошибке audit, права и гонки, compiled standalone/Docker HTTP
и реальный browser UI в Tea/Paper/Night 320/390/1440. В тестах отправка почты выключена,
ключ провайдера отсутствует, внешние server HTTP заблокированы. Production аккаунты
не используются как тестовые и не удаляются.
