## Пользовательские контракты

Четыре вкладки: главы, об истории, отзывы и комментарии, мой дневник.
Пять обязательных целых оценок 1–5 для произведения; одна для главы.
Текст необязателен, максимум 2000 символов. Общая оценка — среднее заполненных критериев.
Один отзыв на пользователя и объект, включая soft-deleted строку. Повторное сохранение
идентичного содержимого возвращает тот же id/version. Изменение требует текущей version;
конфликт возвращает 409 и сохраняет пользовательский черновик на экране.
Удаление мягкое. Новая публикация после удаления использует ту же строку.

Редактор только в модальном окне; собственный отзыв — полноценная карточка.
На desktop справа может показываться read-only сводка, но не постоянно открытая форма.
Закрытие изменённого редактора через Escape, фон или X требует подтверждения.
Есть beforeunload guard, focus restore, body scroll lock, включая вложенный редактор главы.
Черновики не сохраняются в localStorage.

Главы не разворачивают комментарии в списке: один лениво открываемый modal на выбранную главу.
Реакции только +1/-1; 0 снимает реакцию. Одна реакция пользователя на отзыв, смена атомарна.
Самореакции запрещены. Ответов/новых веток для отзывов нет.
Фильтры: все, с текстом, только оценки; новые/старые; keyset pagination по 20 строк.
Спойлеры скрываются до явного раскрытия.

## Совместимость с прежними данными

Исторические community_comments и связи parent_id не мигрируются и не удаляются.
В новом интерфейсе они доступны как свёрнутый плоский архив, без формы ответа.
Владелец может удалить старое сообщение через прежний защищённый API.
Существующие старые API не отключены; старые клиенты всё ещё могут пользоваться прежним
COMMUNITY контрактом. Новый интерфейс и новые reviews API не создают ответы/ветки.

Приватные заметки и личные оценки остаются отдельными данными дневника. Текст личной
заметки никогда автоматически не публикуется. Для общественного рейтинга новый видимый
отзыв имеет приоритет над старой числовой оценкой того же пользователя/объекта.
Пока публичного отзыва нет, прежняя числовая оценка учитывается по прежней политике RATE.
После удаления/скрытия публичного отзыва старая личная оценка автоматически не возвращается
в агрегат: наличие строки отзыва означает переход на новую публичную модель для объекта.
Ни одна операция публикации не переписывает личные оценки/заметки.

## API

- GET `/api/community/reviews?comicId=…[&chapterId=…]&filter=all|text|scores&order=new|old[&cursor=…]`.
- PUT `/api/community/reviews`: `{comicId,chapterId:null|number,scores:number[],body,spoiler,version:null|number}`.
- DELETE `/api/community/reviews/:id`: `{version}`.
- PUT `/api/community/reviews/:id/reaction`: `{value:-1|0|1}`.
- GET `/api/community/reviews/history?comicId=…[&chapterId=…][&cursor=…]` — плоский архив.
- PUT `/api/community/reviews/:id/moderation`: `{action:"HIDE"|"RESTORE",reason}`.
- GET reviews с `filter=hidden` — только действующий ADMIN.

Точную валидацию и DTO определяет review-policy.ts. Неизвестные поля, подмена userId,
parentId, повторные query keys и некорректные оценки отвергаются. Actor только из сессии.
DTO не содержит email, user ID, cookie, хеши и приватные заметки.
Мутагирующие запросы используют существующие Origin/размер тела/сессию/квоты COMMUNITY.
Доступны только SHARED/PUBLISHED произведения и выпущенные связанные главы.

## Безопасность и модерация

Повторно используются existing mutate/lockTarget/consume, а не альтернативная авторизация.
Каталожный advisory lock → USER/SESSION SHARE → per-user control UPDATE → объект/отзыв.
В конце каждой мутации, включая no-op, проверяется expiry по clock_timestamp; logout,
revocation, блокировка и смена роли согласованы через существующие блокировки.
Нет сетевых вызовов внутри транзакции. Уникальные partial indexes защищают от дублей.
Редактирование optimistic version + row lock. Реакции PK(review_id,user_id).
Составной FK(chapter_id,comic_id) защищает принадлежность главы, ON UPDATE CASCADE
сохраняет связь при штатном переносе главы.

ADMIN может скрыть/восстановить отзыв с обязательной причиной. Изменение роли проверяется
в транзакции, действие записывается в существующий moderation audit с review_id.
Скрытый отзыв исключён из публичного списка/рейтинга, автор не может снять скрытие правкой.
Восстановление модератором не отменяет удаление владельцем. Повтор команды не дублирует audit.
Ограничения публикации существующего COMMUNITY действуют и для отзывов.

## Открытый продуктовый вопрос

Время чтения не добавлено: модель не определяет однозначно, идёт ли речь о длительности
чтения главы/произведения, фактическом времени конкретного читателя или справочном времени,
которое задаёт администратор. Нужно согласовать владельца поля, объект и единицу измерения.
До этого ни поле, ни пустой placeholder в интерфейсе не показываются. История оценок/графики
не входят в задачу и не реализованы.
