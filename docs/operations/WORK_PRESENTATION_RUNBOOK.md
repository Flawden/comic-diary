## Данные и совместимость

Аддитивная миграция `0050_work_presentation`: необязательные `chapters.page_count`,
`chapters.reading_minutes`, `comics.age_rating`; `presentation_revision` default 0;
справочник genres и связи comic_genres. Старые INSERT продолжают работать.
Пустые страницы/время/возраст остаются NULL; старые записи не заполняются догадками.
Исторические SQL не меняются; журнал содержит 51 запись.

Страницы и минуты — целые 1–100000. Возраст — NULL или 0/6/12/16/18, выбирается
редактором. До 10 жанров, нормализация Unicode/пробелов, запрет дубликатов.
Старые импортеры и редакторы не перезаписывают новые поля, если не обслуживают их.
Категория каталога остаётся самостоятельной сущностью.

## Работа редактора

В `/admin/comics` выбрать произведение, открыть «Возраст, жанры, страницы и время
чтения» на вкладке метаданных или глав. Жанры вводятся через запятую. У каждой
главы необязательные страницы и примерное время. Кнопка «Сохранить сведения»
сохраняет этот блок отдельно; ENTER в его полях не публикует родительскую форму.

GET/PUT `/api/admin/catalog/comics/:id/presentation`: действующая сессия
EDITOR/ADMIN; PUT требует canonical Origin/Host и JSON, body до 128 KiB.
GET возвращает revision/ageRating/genres и безопасные метаданные глав.
PUT принимает строго `{revision, ageRating, genres, chapters:[{id,pageCount,readingMinutes}]}`;
главы отсутствующие в массиве сохраняются. До 500 изменяемых глав за запрос.
Чужая глава отклоняет всю транзакцию. USER не допускается, PRIVATE произведения
не обслуживаются этим редактором общего каталога.

Сервер повторно проверяет актуальные USER/SESSION/права внутри транзакции.
Порядок: общий advisory catalog lock → USER SHARE → SESSION SHARE → COMIC UPDATE
→ CHAPTER UPDATE по id. Нет повышения SHARE → UPDATE. Revision CAS предотвращает
потерянное обновление: 409 сохраняет локальный ввод и требует проверки свежих данных.
Сохранение метаданных, связей и audit атомарно; ошибка БД откатывает весь блок.
При потере ответа нет автоматического повторения. «Загрузить актуальные данные»
предупреждает о замене несохранённого ввода.

## Расчёты и UX

Том считает опубликованные главы выбранного раздела, без scheduled/archived.
Основные главы и спецвыпуски учитываются в своих разделах. Страницы прочитанных
глав — сумма страниц целиком отмеченных глав, а не наблюдение за внешним VK.
Процент страниц и общий объём показываются только при полном заполнении всех
доступных глав раздела; при частичных данных сообщается полнота заполнения.
Время тома выводится только при заполнении всех соответствующих глав.
Поиск/пагинация не меняют знаменатели. Точных страниц внутри VK сайт не отслеживает.

Рейтинг тома: среднее по оценённым опубликованным основным главам каждого читателя,
затем среднее между читателями. Каждый читатель имеет одинаковый вес; округление
только при отображении. Подпись «По оценкам глав» и число оценивших обязательны.
Применяются прежние правила RATE/Reviews: публичный отзыв заменяет старую оценку
один раз, скрытие/удаление не возвращают старый голос в агрегат.

В оглавлении «Моя · отзыв» открывает существующее окно отзывов главы; «Моя · дневник»
для ранее прочитанной главы — прежний редактор личной оценки. Источник явно подписан.
Удалённый отзыв показывает прочерк, а не скрытно воскрешает дневниковую оценку.
Личные записи и оценки не синхронизируются и не перезаписываются автоматически.
В сводном блоке произведения «Моя оценка» подписана как оценка публичного отзыва.
Пять критериев имеют общий набор SVG-иконок. Отсутствующее значение — `—`,
экранному диктору даётся содержательная подпись; это не нулевая оценка.

## Проверки и rollout

Unit/contracts, PostgreSQL 17 upgrade/replay/data preservation, роли, CAS,
foreign chapter, audit fault rollback, равный вес читателей, hidden/deleted votes.
Реальный локальный browser: редактор, HTTP 401/403/409/413, 3 темы × 320/390/1440,
длинные названия, полные/неполные данные, отсутствие рейтингов и старые Reviews.
Все данные/credentials синтетические, provider HTTP запрещён.

Перед merge — точный SHA, зелёный PR CI, fresh production restore drill и проверка
предыдущего immutable image на схеме 0050. Штатный deployment создаёт отдельный
pre-migration backup и применяет migrator. После него проверить SHA/image, health,
51 migration, сохранённые AUTH-состояния, отзывы, главы и отсутствие новых писем.
Новые поля остаются пустыми до редакторского заполнения; production fake data не создаются.

При неуспешном deployment или внешнем HTTPS smoke остановиться с диагностикой.
Никакого слепого повторного deployment, ручного rollback или восстановления БД.
Возврат предыдущего app image выполняется только отдельным решением; down migration
не нужна: новые поля/жанры остаются в БД, старый UI их не показывает и не удаляет.
