# Comic Diary · ADMIN-CHAPTER-UX-02 — окончательное удаление старой формы глав

**Статус:** ОБЯЗАТЕЛЬНЫЙ БЛОКЕР первого релиза (не выполнен).
**Дата фиксации:** 2026-11-12.
**Входная ветка:** `feature/admin-chapter-ux-01-modal-batch`.
**Входной коммит:** `20fda49e9b58c1d17308f01b32dcb10b28380111`.
**CI входного коммита:** не подтверждён предоставленным отчётом; сначала проверить GitHub Actions.

## Решение

Оставляем **одну** точку добавления глав: «+ Добавить главы», открывающую компактный диалог. В нём можно добавить произвольное количество строк (в рамках существующего лимита 100), вводить ссылку и название, а дополнительные настройки раскрывать только при необходимости. Существующий редактор главы открывается диалогом с заполненными полями. Никаких параллельных старых inline-форм после выполнения UX-02 быть не должно.

## Почему старую форму нельзя просто удалить прямо сейчас

В `src/app/admin/comics/AdminComicManager.tsx` под заголовком «Расширенное создание: том, дата, точный порядок или новая редакция» осталась старая форма. Её возможности ещё НЕ равны текущему пакетному диалогу `src/modules/catalog/components/ChapterBatchEditor.tsx`:

- номер тома для конкретной главы;
- точный `sortOrder` для конкретной главы;
- дата выхода и ожидаемая дата с точностью года/месяца/дня;
- выпуск новой редакции через `supersedesChapterId` с сохранением истории чтения старой;
- дополнительная валидация подтверждения замены старой редакции.

Существующий `batch-preview`/`batch-create` использует текстовые строки из четырёх столбцов (код, название, тип, URL) и общий статус. Продвинутые поля нельзя «тихо отбросить» при массовом сохранении.

## Обязательная реализация

1. **Проверить CI UX-01.** При ошибке сначала исправить фактическую проблему.
2. **Перенести все перечисленные возможности в новый диалог** с интуитивно скрытыми настройками. Если расширяются возможности нескольких строк одновременно, расширить batch-preview и batch-create на сервере с атомарной транзакцией и полной проверкой данных. Не посылать 20 последовательных POST как якобы атомарный пакет.
3. **Сохранить совместимость редактирования:** заполненные поля, без случайной публикации, возможность сохранить и перезагрузить страницу без потери данных.
4. **Защитить историю чтения при замене редакции:** старая глава архивируется, записи чтения остаются привязаны к исторической записи, проверка на сервере остаётся строгой.
5. **Удалить старый UI-код полностью:** `<details>` с «Расширенным созданием» в `AdminComicManager.tsx`, старую кнопку «Создать главу / редакцию», неиспользуемые состояния, обработчики, импорты и вспомогательные функции после проверки реальных использований. Не заменить CSS-скрытием или `hidden`.
6. **Не переписывать старые значения `sortOrder` без отдельного аудита данных.** В обычном UI показывать последовательную позицию и `displayCode`, ручной технический индекс — только в дополнениях.
7. **Добавить браузерные регрессии:** пакет из нескольких глав, том/даты/ручной порядок, замена редакции, редактирование, отмена, ошибки валидации, права обычного пользователя, отсутствие старого редактора в DOM; убедиться в отсутствии частичных сохранений.
8. **Перед релизом:** `npm` typecheck, браузерный CI и мобильная визуальная проверка — зелёные на интегрированной feature-ветке. Без merge в `master` или деплоя до отдельного решения.

## Чёткий критерий «ГОТОВО»

**В админке ровно один интерфейс создания глав, ни одной старой скрытой или раскрываемой формы, все сохранённые возможности доступны и тестируются; новая ветка CI зелёная.** Только тогда закрывать ADMIN-CHAPTER-UX-02.
