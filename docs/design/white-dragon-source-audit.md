## Найденные ограничения данных

- get-user-library.ts возвращает categoryName, но не categoryId/slug и не sourceUrl. Для ссылки на общий источник нужно добавить sourceUrl в существующий запрос с сохранением изоляции владельца. Для коллекционных подсчётов нужна устойчивая идентичность категории; имя не бизнес-ключ.
- updatedAt в user_comics — время изменения записи, включая нечитательские изменения. Нельзя подписывать сортировку «последнее чтение» без отдельного события. В первой версии — существующий UPDATED и честная подпись «Недавно изменённые».
- getUserLibrary вызывает getChapterReading для каждой записи; каталог аналогично получает ceiling по каждому тайтлу. Это повод измерить число запросов на большом каталоге; необходимость оптимизации не доказана замером.
- getChapterProgressCeiling считает только RELEASED MAIN. getUserLibrary для реестра использует результат getChapterReading, а для legacy оставляет числовой прогресс и null ceiling. Новая карточка должна уважать это разделение.
- Следующая непрочитанная глава не обязательно currentChapter+1. До отдельного проверенного resolver использовать честную ссылку на общий источник; точную главу показывать только по данным реестра и её sourceUrl.
- Подпись VK допустима только для распознанной VK-ссылки. Существующие источники общие: для остальных «Открыть источник». Отсутствующую ссылку не выдумывать.
- В библиотеке уже есть query/status/sort. Изменения отображения не должны сбрасывать их; возврат из карточки требует отдельной проверки.
